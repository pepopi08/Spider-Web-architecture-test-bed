<details> <summary>ivARCH classification (inportant!):</summary>
ivARCH, that is, instruction-value architecture, was based, as you might expect, on instructions and values. The principle was as follows: a value, an abstract token, for example, numbers, was embedded inside an empty parameter. To move to the next token (overall, graphically this looks like weighting coefficients), conditions had to be met. Inside the conditions, a clause was embedded, such as, for example, a plus sign. That is, to achieve the next parameter in the formula 2+3=5, to reach 3 in logical progression (see the explanation below), it was necessary to perform the operation of layering the weight category 2 onto 3, which initially created the answer 5. That is, the instruction is a deliberate obstacle to advancing the horizon of AI events, and to progress, it must meet the conditions. For example, to progress up the career ladder at work, you need to work hard. Essentially, parameters 1 and 2 here represent your current and future positions, while the instruction is your future position. Moreover, any situational token from the AI training dataset can serve as a value. The main problem with this architecture was that it did not allow for operation within a graphical tree structure, nor within a network, let alone a web — that is, the parameters could go into a cyclical progression but not be linked to each other. 
Spider-web, while preserving the best features of its predecessor, also added the ability to link parameters at any fractal levels, layers, and literally any created or to‑be‑created parameter with any other. </details>
